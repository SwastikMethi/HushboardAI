## Rulings

Decisions taken where the plan or handoff left a choice, each with what it costs if wrong.

1. **Git and workspace.** One repository in this folder on `main`, one commit per milestone, nothing pushed — the owner's choice. No separate worktree: the repository starts empty, so there is nothing to isolate from. Cost if wrong: none; history can be rebased onto a branch.
2. **This file is the ledger.** The executing-plans workflow's own ledger scripts expect a task-numbered plan; the approved plan is milestone-based, and the handoff already requires `PROGRESS.md`. Cost if wrong: none.
3. **Java-only interop; no Kotlin bridge file.** `sdkbridge/DesertAntClient` calls suspend functions through the coroutines library's future builder. Cancellation releases the caller and vendor exceptions surface as the cause of an `ExecutionException` — both proven on the emulator. `SuspendCall<T>` takes `Continuation<T>` (not `? super T`) so method references infer `T`; the single unchecked cast this needs is safe because a continuation only consumes `T`. Cost if wrong: add the one Kotlin file the handoff permits.
4. **The app downloads model files itself; the SDK's `download()` is not used in product code.** The spike showed an SDK download cannot be cancelled: the transfer runs on after the caller is released, which would break the Cancel button and the "unmetered networks only" promise. The app fetches the exact files the SDK pins (public URLs, `Range` resume, SHA-256 check) into its own directory, and the SDK adopts that directory — proven offline. `isDownloaded()` stays the final acceptance check before a model is marked Ready. Cost if wrong: a device that needs a different file set shows the model as Failed with the reason; the fallback is the SDK's own uncancellable download.
5. **Vendor artifacts are added as their adapters land**, not all 13 at once: each native model adds about 56 MB (703 MB for all). Cost if wrong: none; `libs.bundles.desertant` restores the full set.
6. **No release build type and no `proguard-rules.pro`.** The deliverable is the debug-signed APK; a release build needs the owner's keystore. Cost if wrong: add both when a release is wanted.
7. **`emoji2-emojipicker` stays at 1.7.0.** It passes the metadata check at compileSdk 36.1 and works inside the IME window. Cost if wrong: drop to 1.6.0.
8. **Backspace is a `KEYCODE_DEL` key event** so the host editor applies its own grapheme rules. Cost if wrong: an editor that ignores key events needs a `deleteSurroundingText` fallback.
9. **The kill and offline probes are opt-in tests.** They need an adb step between or before them, so they skip in a plain run. Cost if wrong: none; commands are in the validation report.

10. **The bundled word list is written for this project** (`assets/dictionaries/en_common.txt`, about 900 common English words in rough frequency order), so it carries no third-party license. Ceiling: single-word completion and one-edit repair only, small vocabulary, no next-word prediction. Upgrade path: AOSP LatinIME's Apache-2.0 word list, which needs the owner's go-ahead to download. Cost if wrong: suggestions are sparse; typing is unaffected.
11. **No composing region.** Characters are committed directly and a picked suggestion replaces the current word through the guarded `replaceRange`. Cost if wrong: none seen; revisit only if an editor mishandles `setComposingRegion`.
12. **A restart of the same field keeps the current layer and shift state.** Some apps restart input on every change; resetting to letters each time would make symbols untypeable. Cost if wrong: a stale layer after a programmatic text change.
13. **Long-press on space opens Android's keyboard picker.** The system already shows its own switch button in the navigation area; this is the in-keyboard route. Cost if wrong: add a dedicated globe key.
14. **Key glyphs are text characters for now** (shift, backspace, enter, the emoji key). The mockup's drawn icons are a milestone 8 item. Cost if wrong: a device font missing a glyph shows a blank key; the audit checks this on the phone.
15. **Haptics default on, key sound off, height standard.** The mechanics exist in milestone 1; the saved settings that control them arrive with the settings store in milestone 2.
16. **The tool row shows only the settings button until there is something real to add** — the AI control in milestone 3, the microphone in milestone 6. The mockup's clipboard and grid icons have no specified behaviour and stay out.

17. **Readiness is file-based, and the SDK's `isDownloaded()` is checked when a model is first loaded, not when it finishes downloading.** Every file is verified against the size and SHA-256 the SDK itself pins, so loading the 56 MB native library just to ask again at download time would cost memory for nothing. If the SDK ever disagrees at load time, the model is marked Unavailable on this device and is never called — which also keeps the rule that typing can never start a download. Cost if wrong: a device needing a different file set finds out at first use instead of at download.
18. **No foreground service for downloads.** The app's downloader resumes, so when WorkManager's 10-minute limit or a network change stops a transfer it continues later from where it stopped (proved by the Wi-Fi test). Cost if wrong: very large models on slow links take several runs to finish.
19. **Cancel removes the partial download; a failure or a pause keeps it.** Cancel is the user saying "not now", so storage is given back. Cost if wrong: a cancelled large download starts again from zero.
20. **Settings and model-detail screens use `androidx.preference`** backed by the shared settings store, rather than hand-built rows. One new dependency replaces a lot of UI code and gives the detail screen its "render any model from its definition" behaviour. Cost if wrong: less visual control; the mockup's rounded group cards are deferred to milestone 8.
21. **Models without a captured file list show "Coming later"** and offer no download. That is nine of the thirteen today; each flips to downloadable when its adapter lands. Cost if wrong: none — the alternative is a button that does nothing.
22. **Android glue (repository, worker, settings store) was written together with its device tests**, not strictly after a failing test. Their decision logic lives in classes that were test-first (`ModelDownloader`, `AppSettings`, `ModelRegistry`), and each device test was watched failing before the wiring that makes it pass. Cost if wrong: thinner unit coverage of the glue itself.

23. **Adapters block the inference thread while the SDK works.** `ModelAdapter.run` waits on the SDK's future there, and only there; the main thread never waits. One thread means one model call at a time, which is the "one heavy slot" the plan asks for and what serialises access to each native model. Cost if wrong: a slow voice model would delay an emoji suggestion; split the slot then.
24. **Emoji fill the strip only when no word is being completed.** While a word is half-typed the strip shows completions; in the pause after it, emoji. The mockup shows emoji after a finished word, which is this case. Cost if wrong: emoji appear less often than some would like.
25. **Text is not read for AI at all in a field where AI may not run.** Eligibility is decided first; only then is the bounded window around the cursor read (1,000 characters before, 200 after). Cost if wrong: none.
26. **The AI panel lists only models that act while typing and have a working adapter** — Emo today; Redact and Toxic join in milestone 4. Cost if wrong: none; a listed switch that did nothing would be worse.
27. **The master switch in the keyboard uses a solid AI-blue track rather than a drawn gradient.** The gradient identity is on the tool-row control (sparkle and border). Cost if wrong: a milestone 8 polish item.
28. **`ModelInput`, `ModelResult`, `ActivityEvent` and `CapabilityRouter` were not created.** `ModelAdapter<I, O>` is generic over its input and output, so wrapper types add nothing yet; routing is one check in `AiCoordinator`. They are added only if the voice and image milestones show a real need. Cost if wrong: a small refactor when a second input kind arrives.

29. **The app masks span by span; the SDK's own masked string is not used.** Each replacement is checked against the editor's current text and all of them apply as one edit or not at all. Cost if wrong: none; the placeholders are the SDK's own.
30. **A span that starts inside a character begins after it** (and after the space that follows); one that ends inside a character takes the rest of it. Seen with the real model: a name span that began inside a family emoji. Cost if wrong: in the rare case where the cut character was part of the item (a decomposed first letter), that letter is left unmasked.
31. **A notice or an undo offer outranks word completions in the strip.** They appear only after typing pauses, and a notice hidden behind completions (an email address at the end of a draft completes like a word) would be missed. Cost if wrong: completions are unavailable while a notice is showing; Dismiss brings them back.
32. **Toxic "alert frequency" is the app's own setting.** The model runs with its shipped thresholds and returns them; the app shifts them (+0.15 for fewer, −0.10 for more) when deciding what to flag. The settings screen says this is set by the app. Only the wording labels (hateful, abusive, threat) are used; the "who is targeted" labels are not surfaced. Cost if wrong: the shifts are untuned starting values.
33. **The undo offer lasts until the next key press.** It is guarded (the placeholders must still be exactly where they were put) and is forgotten when the field loses the keyboard. Cost if wrong: an undo wanted after more typing is not offered.
34. **Tone notices offer no edit.** Review shows which kinds of wording were flagged and says the model is in beta; there is nothing to apply. Cost if wrong: none.

35. **Tongue gates Redact only.** Redact's language list is the one the vendor documents precisely; Emo's and Toxic's exact lists were not captured, so nothing is claimed or gated for them. Cost if wrong: Emo or Toxic may run on a language they handle poorly.
36. **Tongue's telemetry switch is left at the vendor default.** The SDK exposes `setSendsDeviceContext`; what "device context" contains is not established, and the license forbids disabling its check. Not touching it keeps the app within what the owner accepted. Cost if wrong: more device detail is sent than the Privacy screen describes — to be settled by reading the vendor's documentation. *Settled in the final review for this SDK version: the Tongue 4.3.0 library contains no network code at all (22 classes; no sockets, HTTP, threads, files or Android references), so the switch cannot send anything. Re-check on an SDK upgrade.*
37. **Gist's useful action is "Tag this draft" → "Insert as hashtags".** Topics are computed only on that tap, shown first, and inserted at the cursor only on a second tap, built from each topic's fixed slug. Cost if wrong: a different action (copy, label) would be a small change.
38. **Model file lists are captured with an opt-in probe that lets the SDK download once** (`ManifestCaptureTest`). It is development tooling, not a product path. Cost if wrong: none.

39. **Voz is refused on devices with under 5 GiB of memory, and unloaded 20 seconds after its last use.** Measured on the emulator: the app's resident memory peaked at 3.9 GB with Voz loaded, and a 3 GB device killed the app while loading it (the crash breaker then switched Voz off — a real recovery, not a simulated one). The 5 GiB line refuses only devices that certainly cannot hold it; the breaker covers the uncertain middle. The 20 seconds keeps a second dictation quick without leaving 4 GB in the keyboard process. Cost if wrong: the line is from one emulator measurement — a 6 GB phone may still be killed once (then Voz is switched off with the reason shown), or a capable 4 GB-class device is refused. Re-measure on real phones.
40. **Testing moved to a dedicated emulator, `AiKeyboard_Test`** (Android 17, 16 KB pages, 8 GB memory, 16 GB storage), defined by two new files under `~/.android/avd/`. The owner's `Pixel_6_Pro` AVD holds another of their apps and filled up; it was not resized or cleared. Cost if wrong: delete `AiKeyboard_Test.ini` and `AiKeyboard_Test.avd` to remove it.
41. **Dictation in the keyboard is record → preview → Insert.** The microphone button shows only while Voz is switched on, installed and allowed in the field; a recording is capped at 60 seconds, stops when the keyboard leaves the screen, and its transcript is typed only when the user taps Insert. Longer audio and the other four voice models belong to the Voice tools screen. Cost if wrong: one extra tap per dictation compared with typing as you speak.
42. **Voice tools process at most two minutes per recording or import**, in one batch (the SDK has no streaming call), and say so when a longer file was cut. Cost if wrong: raise `VoiceToolsFragment.MAX_SECONDS` once memory use on long audio has been measured on a phone.
43. **Audio is converted to mono 16 kHz by linear interpolation with no low-pass filter.** Fine for speech; marked in the code as the thing to replace if music or export quality ever matters. Each model is told the sample rate of what it is given, so Clear's 48 kHz output passes straight on. Cost if wrong: aliasing on audio with content above 8 kHz.
44. **Ear's language is shown as information only.** Voz takes no language parameter and its language list was not captured, so nothing is gated on the hint and nothing is claimed about which languages transcribe well. Cost if wrong: none; a mismatch shows as a poor transcript next to the detected language.
45. **Who returns no turns for short clips, and the screen simply shows no speaker labels then.** Seen with the real model: nothing for 7 seconds of speech, turns for 20 seconds. Cost if wrong: none.
46. **Shared audio is written to the app's cache and deleted once it is an hour old** (checked at each share and at each app start); recordings and transcripts are otherwise held in memory only and are gone when the screen is left. Cost if wrong: an app that reads the shared file more than an hour later finds it gone.
47. **`AppContainer.capture` is replaceable.** Device tests put known speech where the microphone would be, so the keyboard and Voice tools flows can be checked against what was actually said; the real recorder has its own test on the emulator's microphone. Cost if wrong: none in the product — nothing in the app replaces it.
48. **A file that cannot be read as audio gets one plain message**, whatever the underlying reason (no audio track, unsupported encoding, not a media file). Cost if wrong: less specific help for an unusual file.
49. **Voice tools open from the Voice group on the Models tab and from each voice model's own screen** ("Try it"), since the handoff's three tabs give them no place of their own. Cost if wrong: a fourth tab is a small change.
50. **Clear is offered everywhere and relies on the crash breaker where it cannot run.** It crashes natively on an emulator drawing in software and runs with a real GPU; its API has no CPU option and the app has no reliable way to tell in advance. A device where it fails loses the app once, then finds Clear switched off with the reason shown. The emulator is started with `-gpu host` so Clear can be tested at all. Cost if wrong: on a phone whose GPU delegate fails, the first use of Clear closes the app once.
51. **A model the app switched off after a crash says so in the catalog** ("Switched off after it stopped the app. Switch it on to try again."), not only in the keyboard's AI panel. Voice models never appear in that panel, so without this the switch would just be mysteriously off. Cost if wrong: none.
52. **Settings writes are applied one at a time, in the order they were made.** A test showed the data store's own asynchronous writes could land out of order (a value written earlier arrived last). Harmless at tapping speed, but the master AI switch is a privacy control, so order is now guaranteed by a single writer thread. Cost if wrong: none; a write waits its turn for a few milliseconds.
53. **Every voice, image and drawing model is unloaded 20 seconds after the last use of any of them**; the typing models stay loaded. This replaces the Voz-only unload of ruling 39 (its memory line still stands) after Eye turned out to hold about 1.5 GB. Eye is also refused below 2 GiB of device memory. Cost if wrong: a tool used again after a pause pays its load time again (about 2 s for Eye, 4 s for Voz on the emulator).
54. **A picked picture is held in memory at up to 1600 pixels across and never copied to disk**, and that scaled copy is what Share sends, as a JPEG. The handoff's "copy into our own cache" was dropped: the system photo picker hands over the one picture, and nothing needs to outlive the screen. Cost if wrong: someone wanting to share the full-size original has to do it from their gallery.
55. **Moderator warns; it never blocks.** A flagged picture shows the score and asks "Share it anyway?"; the choice stays with the user. The flag is the model's own decision at its own threshold, which is the one setting offered. Because no explicit imagery was used, the flagged path was exercised by setting that threshold to zero — the warning flow is proved, the model's detection quality is not. Cost if wrong: none for the flow; the detection quality needs someone to judge it with real material.
56. **Eye's result is shown in the model's own English words** (its kind and its six most confident tags, underscores turned into spaces), with counts of people, pets and faces and its "looks" score. The other things Eye returns (crops, sharpness map, per-face details, duplicates) are not surfaced. Cost if wrong: more of the result can be shown later; nothing depends on it.
57. **Drawing is one stroke at a time.** The stroke is tidied when the finger lifts; a new stroke replaces the last. What the model calls a scribble, or returns nothing for, is shown as "No clear shape. Try again." and the stroke stays as drawn. A shared or inserted drawing is dark ink on white so it reads in any chat. Cost if wrong: multi-stroke drawings would need the app to keep and combine shapes.
58. **The keyboard has a drawing panel, and its button says what it will do.** In a field that declares it takes `image/png` the button is Insert and the drawing goes in through `commitContent` with a read grant; anywhere else it is "Share…" and the system share sheet opens. If a host that claimed to take pictures turns the insert down, the share sheet is offered as well. Cost if wrong: an app that accepts pictures only by another route gets the share sheet, which still works.
59. **A drawing is not kept across a screen rotation**, and the Image tools result is (it lives in a ViewModel). Cost if wrong: a doodle is lost on rotation; save the stroke in the view's state if that matters.
60. **The image and drawing screens open the same way as Voice tools**: from their group on the Models tab and from each model's own screen (ruling 49).
61. **No explicit or sensitive test imagery was created or downloaded** to test Moderator or Eye's NSFW tags. Cost if wrong: see ruling 55.
62. **The keyboard keeps one footprint.** Its root (`ime/view/KeyboardFrame`) measures the typing area and gives every panel exactly that height; a panel with more in it scrolls inside. Found in the audit: with five models the AI panel had grown about 110dp taller than the keyboard and pushed the app up. The panel now shows three models at a time like the approved design, reopens at the top each time, and "Tag draft" moved into its footer so the list keeps its room. Cost if wrong: Tongue and Gist are one scroll away in the panel.
63. **Tool row: draw at the left edge; microphone, then settings at the right edge.** The approved design puts settings before the microphone, but the microphone comes and goes with Voz, and settings should not move when it does. The design's clipboard and grid buttons stay out (ruling 16). Cost if wrong: swap two buttons.
64. **Every icon is drawn for this project**: one line icon per model, the AI sparkle, shift and backspace keys (replacing the font glyphs of ruling 14), a chevron and the app icon. No icon set was downloaded. Cost if wrong: they are simple; a designer may want to redraw them.
65. **Switches have a white thumb on a blue track everywhere, and the master AI switch carries the violet-to-blue gradient** in the keyboard and in the app (replacing ruling 27). One accent colour is set for every control, which removed a stray lavender from sliders and headings. Cost if wrong: none.
66. **Settings and model screens draw their rows as grouped cards** (replacing the flat lists of ruling 20) with a small painter behind the standard rows. Still different from the companion reference: a choice such as "When detected" opens a list instead of showing a two-part toggle, settings rows have no icons, and "Try it" shows its result as text rather than a chip. Cost if wrong: visual only; the behaviour is the same.
67. **Theme and Languages are shown as facts, in words**: "Dark. The only theme in this version." A row that looked tappable and did nothing would break the rule that every control works or says it is unavailable. Cost if wrong: remove the two rows.
68. **The tool row is 48dp high and the strip 44dp** (were 44 and 40), so their buttons are full-size touch targets. The keyboard is 8dp taller. Cost if wrong: two numbers in `dimens.xml`.
69. **Key shapes are low-contrast against the keyboard on purpose** (about 1.5 to 1, like stock keyboards); what is read is the label, which is over 10 to 1. Every text and control colour pair that carries meaning is checked against the WCAG ratios in `AccessibilityAuditTest`. Cost if wrong: lighten `key_letter`.
70. **The accessibility audit is automated, not a person using a screen reader.** The app's screens pass Google's accessibility checks; the keyboard's controls are checked for spoken labels and size through the accessibility tree; a canary proves the checks can fail. Nobody has yet used the keyboard with TalkBack switched on. Cost if wrong: order of announcement or wording problems that only a real pass would find — for the phone session.
71. **The license check was not captured on the wire.** The SDK keeps a signed record per model per month, so a check only happens on a model's first load in a month; forcing one (by deleting that record) would register another activation with the vendor, which is not this project's to spend. What is established: model runs send nothing, and reloading models with current records sent 40 bytes. The Privacy screen's wording was corrected from "each time a model is loaded" to "the first time a model is used, and again from time to time (about once a month for each model)". Cost if wrong: the check may contain more than the vendor's documentation says; the owner can capture it on a fresh install with a proxy.
72. **Process death, sleep/wake and offline start were checked by hand over adb**, not by automated tests: the tests run inside the app's own process, so they cannot outlive its death. The commands and results are in the validation report. Cost if wrong: these three are not re-run by the test suite.
73. **The Privacy screen now covers recordings, pictures and drawings**, added in this milestone because milestones 6 and 7 introduced them. Cost if wrong: none.

Rulings 74–89 were made in the final review (see "Final review" below for what was fixed and what was deferred).

74. **Final: the reviewer's "a restart carries the last field's dictation and notices into the next field" was not reproduced, and nothing was changed for it.** `KeyboardVoiceTest.movingToAnotherFieldEndsTheDictation` passed before any change. Since the password fix, the session is also dropped whenever input starts on a field. A restart of the *same* field still keeps the layer and shift state on purpose (ruling 12). Cost if wrong: a host that swaps content inside one field without moving focus could keep an undo offer or the symbols layer for one more key press.
75. **Final: backspace and plain Enter are now sent marked as on-screen-keyboard presses, without a failing test first.** They carry real times and the soft-keyboard flags, the way the platform's own `sendDownUpKeyEvents` sends them. `KeyboardImeTest.backspaceAndEnterLeaveTheAppInTouchMode` passes before and after on Android 17, so it guards the behaviour but did not prove a problem. Cost if wrong: none expected; revert `EditorBridge.sendKey`.
76. **Final: a key pressed while the keyboard has no session starts one from the field in focus** (`KeyboardController.onKey`). A safety net added with the password fix, for a host that shows the keyboard without telling it a field started. No test drives that order of events. Cost if wrong: on such a host the first key press behaves as in a fresh field.
77. **Final: seven findings the reviewer called minor were re-graded by what a person would get, and fixed.** Overlapping edits could mangle a draft; selecting a long note handed all of it to the models; a status label looked tappable and did nothing, and Tag was offered on an empty draft; a damaged settings file or a settings error took the keyboard down; the app used the network on the strength of the SDK's permission only; the key events of ruling 75; and report statements that were no longer true. Cost if wrong: none; all but ruling 75 have a test that failed first.
78. **Final: recording from inside the keyboard on real phones stays a blocked row.** The emulator records. A phone that will not give a keyboard the microphone shows "the microphone couldn't be opened" and typing carries on. Cost if wrong: no dictation on that phone, with a message. Phone session.
79. **Final: Clear on real GPUs — ruling 50 stands.** Cost if wrong: as ruling 50, the app closes once and Clear is then switched off with the reason.
80. **Final: Voz's 5 GiB line — ruling 39 stands.** One emulator measurement. Cost if wrong: as ruling 39.
81. **Final: the time spent asking the host app for its text on each change was not measured.** The keyboard reads at most 1,200 characters once per change. In a host that answers slowly this would be felt as key lag. Cost if wrong: lag in that app; the remedy is to read after the typing pause instead. Phone session.
82. **Final: WhatsApp, Telegram, Discord, a browser, and fields that declare no input type were not run anywhere.** The chat apps wait for the phone. Fields with no input type (terminals, some games) expect raw key presses, and this keyboard commits text; whether letters arrive there is unknown. Cost if wrong: typing does not work in such apps until letters are also sent as key events there.
83. **Final: whether Redact can return overlapping spans is left unanswered, because it can no longer damage text.** Overlapping or out-of-order edits are refused as a whole and nothing is changed. Cost if wrong: on such a draft masking never applies, and the message shown says the text changed, which would not be the real reason.
84. **Final: what the license check sends — ruling 71 stands.** Cost if wrong: as ruling 71.
85. **Final: the reviewer could not vouch that the native voice, image and drawing libraries stay off the network; that is now measured.** Zero bytes sent and received across all eight, with their models loaded. One full run showed 80 bytes; that was a download's connection closing, not a model (ruling 89). Cost if wrong: none for what was measured; the first load of a model in a month still makes the license check.
86. **Final: how close the screens are to the designs, a TalkBack pass, and how good each model's answers are remain the owner's to judge.** Nothing automated can settle them (ruling 70, open items). Cost if wrong: polish and wording problems found late.
